# AGENTS.md – for coding agents modifying this repository

## Project overview

This repository holds an open WNBA lineup-stint dataset (48 JSON files under `data/stints/`) plus a small Python package (`luma_wnba`) that provides a stdlib-only loader for it. The package has zero runtime dependencies by design and is distributed via `src/luma_wnba/`.

## Repository layout

```
data/stints/rs_YYYY.json, po_YYYY.json   the corpus, 48 files
data/crosswalk.csv                       player identity
data/quality.json, data/manifest.json    diagnostics, SHA-256 per file
data/metrics/{arc,rapm,od,channels}/     rating boards
src/luma_wnba/__init__.py                the loader package
src/luma_wnba/cli.py                     console entry point
notebooks/quickstart.ipynb               Colab quickstart
loaders/python/luma_wnba.py              deprecated shim, keep working
llms.txt                                 briefing for AI assistants using the data
SCHEMA.md, METRICS.md, SOURCES.md        documentation
```

## Setup

```bash
pip install -e .
```

There are no runtime dependencies and none should be added. All required modules are from the Python standard library.

## Testing

CI runs all of this on every push, see `.github/workflows/verify.yml`.

```bash
# Verify loaded stints (use local data directory)
python -c "import luma_wnba as l; g=l.load_stints(2026, source='local', data_dir='data'); print(len(g))"

# Build the package
python -m build

# Check the distribution
python -m twine check dist/*
```

The notebook (`notebooks/quickstart.ipynb`) must be executed with `nbclient` in a clean virtualenv **without** `luma_wnba` installed, because the install cell in the notebook is part of what is being tested.

## Conventions

1. The package must remain standard library only. Do not add dependencies to `pyproject.toml`.
2. Support Python 3.8 and newer. Do not use `match` statements, walrus operators in public code, or f-string equals specifiers (`f"{x=}"`).
3. Public API is the `__all__` list in `src/luma_wnba/__init__.py`. Adding a name there is a breaking change to the documented surface, so update `llms.txt` in the same commit.
4. Never rewrite files under `data/` by hand. They are generated by the upstream pipeline and checksummed in `data/manifest.json`.
5. Player ids are `LUMA-W-#######` and are immutable. Never renumber them.
6. Notebook cells must keep trailing newlines in their source arrays, per `nbformat`. A cell written without them collapses into one line and silently breaks.
7. Keep `loaders/python/luma_wnba.py` working. It is a deprecated shim that some existing scripts still import.

## When you change the API

Do not update the docs by hand. Run:

```bash
python scripts/sync_docs.py
```

That rewrites every generated block from the live code. CI runs
`python scripts/sync_docs.py --check` on each push and fails if anything drifted,
so a stale doc cannot reach main.

Generated blocks are delimited and must not be edited manually:

| file | blocks |
|---|---|
| `llms.txt` | `api`, `coverage` |
| `README.md` | `api` |
| `AGENTS.md` | `api` |

Anything outside those markers is prose you maintain yourself. If you change a
function name or signature, the only manual edits needed are the surrounding
explanation and, if the behaviour changed, `notebooks/quickstart.ipynb`.

## Data invariants

- Regular season and postseason never share a game id.
- Stint positions denote venue (home/away), not franchise.
- A small number of stints have non-positive seconds and must be skipped.
- Tallies are 16 integers in the order of the `TALLY` constant.

## Commit style

One line: imperative subject under 72 characters, blank line, then why the change was needed and how it was verified. No emoji. No marketing.
